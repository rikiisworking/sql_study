Spark / Glue

Look atSkew looks like
Stage → Event Timeline One (or few) tasks far longer than the rest
Stage → Summary Metrics Max duration / records / spill ≫ median (and 75th)

Levers (stop at the first that fits):

  1. Filter/project, then broadcast the small side
  2. AQE skew join: spark.sql.adaptive.enabled + spark.sql.adaptive.skewJoin.enabled (Glue 4: AQE default on)
  3. Higher-cardinality or composite join key, if the question allows it

Table skew SELECT "table", diststyle, skew_rows FROM svv_table_info; skew_rows = max-slice rows ÷ min-slice rows. Diagnostic query treats ≥ 4.00 as “reconsider dist.”
Query skew SVL_QUERY_REPORT for the query id; same segment/step, compare rows and elapsed_time across slices Large slice gaps ⇒ this query’s work is uneven (even if the table looks even)

Date trap: DISTKEY on a date + “last N days” filter → few slices do the work. Prefer a key that stays even after the usual predicates.
