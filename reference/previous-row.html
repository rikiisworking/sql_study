Previous row per key

Attach the last version. Use with lesson 0009. Pair with latest-per-key.

Portable

SELECT
  t.*,
  LAG(status) OVER (
    PARTITION BY customer_id
    ORDER BY updated_at ASC, event_id ASC
  ) AS prev_status
FROM events t;
  • PARTITION BY = entity whose history you walk
  • ORDER BY = time forward, then a unique tiebreaker
  • First row in each partition: LAG is NULL (no earlier row)
  • LEAD is the same idea looking forward

Flips (exclude “no previous”)

WITH lined AS (
  SELECT
    t.*,
    LAG(status) OVER (
      PARTITION BY customer_id
      ORDER BY updated_at ASC, event_id ASC
    ) AS prev_status
  FROM events t
)
SELECT *
FROM lined
WHERE prev_status IS NOT NULL
  AND status <> prev_status;

Bare status <> prev_status is UNKNOWN when prev_status is NULL — WHERE drops the row. That is not a flip. See lesson 0002.

Do not confuse

ShapeUse
LAG + time ASC Previous version; keep every row
LEAD + time ASC Next version
ROW_NUMBER + time DESC, rn = 1 One current row (lesson 0008)
Self-join on MAX(earlier ts) Wrong neighbor on timestamp ties; can fan out
SUM() OVER (ORDER BY …) Running total — default frame, not LAG. Later, if needed.

Vendor notes

  • PG / Redshift / Spark: LAG(value [, offset [, default]]); offset default 1; default value default NULL.
  • Redshift: OVER for LAG cannot take a frame clause.
  • Redshift / Spark: optional IGNORE NULLS. PostgreSQL: always respect nulls (standard default).
